# v4 검증 및 운영 승격 기준

## 검증 범위와 현재 판정

이 문서는 v3.2 원문을 읽고 작성한 설계 검토와 인수 시험 명세다. 아래 전체 매트릭스는 **운영 인수 시험 명세**다. 이번에 실행한 부분 집합은 validation-report.md에 별도로 기록한다. 합성 데이터 시험과 실제 Drive 운영 시험을 구별한다.

| 증거 수준 | 현재 상태 | 허용되는 설명 |
|---|---|---|
| 설계 검토 | v3.2 범위·식별자·출처·완료율·동기화 설계 검토 | 설계상 결함과 보완 기준을 식별함 |
| 계약 시험 | 일부 참조 계약 실행 완료; validation-report.md 참조 | 실제 결과·커밋·명령·로그가 있는 시험에 한해서 별도 시험 보고서에서 통과 표시 |
| 실제 Drive 실행 | 전수 목록화·변경 재생·전수 추출 증거 없음 | 대표 폴더 관찰은 전수 실행 검증을 대체하지 않음 |

배포 단계를 `설계 검토 → 계약 시험 → 제한된 실제 자료 시험 → 전수 인벤토리 운영 → 형식별 콘텐츠 운영 → 법규 기능 운영`으로 구분한다. 앞 단계 통과를 뒷 단계 완료로 표시하지 않는다.

## v3.2 감사 결과 및 필수 수정

1. **스캔 중 변경 경합:** 초기 전수 스캔을 시작하기 전에 범위별 변경 시작 토큰을 확보하고, 목록 완료 후 토큰부터 변경을 재생해 수집 중 추가·삭제·이동을 보정해야 한다. 이후 주기적 대조로 가시성 변화도 확인한다.
2. **인벤토리 분모:** API가 알려주지 않는 전체 파일 수를 추정 분모로 삼아 100%를 표시하면 안 된다. `열거된 고유 ID 수`, `완주한 범위 수`, `미완료 범위 수`, `오류 페이지 수`, `기준 시점`을 함께 제시한다.
3. **분류 큐의 의미:** 검토 큐에 넣은 것은 처분 기록 완료이지 분류 확정 완료가 아니다. `처분 기록률`과 `관련성 확정률`을 분리한다. 무관 판정의 오탐 제외를 검증하지 않으면 모든 건축 문서 확보를 주장할 수 없다.
4. **아카이브 ID:** `Drive ID + 내부 경로`만으로는 ZIP 교체 시 과거 항목이 덮어써진다. 원본 콘텐츠 스냅샷 ID와 내부 항목 경로·순번을 포함한다. 같은 경로의 중복 엔트리도 구별한다.
5. **접근 상실:** 과거 출처 보존과 현재 사용자의 열람 권한은 독립적이다. 원본 접근을 잃으면 검색·미리보기·스니펫·다운로드에 남아 있는 파생 콘텐츠도 권한 정책에 따라 차단한다.
6. **스냅샷 경합:** 다운로드 전후 버전이나 수정 정보가 달라지면 하나의 일관된 스냅샷으로 승인하지 않는다. 재시도 또는 불확실 상태로 보존한다. 네이티브 문서 내보내기에 안정 버전 보장이 없는 경우 그 한계를 기록한다.
7. **예외와 완료:** 승인된 예외는 성공 추출이 아니다. T2 아티팩트 연결, T3 완전 추출, 부분 추출, 미지원, 승인 예외의 분모와 건수를 따로 제시한다.

## 형식별 실제 파일 검증 게이트

최소 표본 개수를 일률적으로 정해 정확성을 보장했다고 주장하지 않는다. 전수 인벤토리에서 발견한 **형식·제작 버전·크기·언어·스캔 여부·암호화·참조 구조**를 층화하여 선택하고, 흔한 정상 파일과 실패 가능 파일을 모두 포함한다.

- DWG/DXF: 레이아웃·문자·블록·좌표·단위·XREF에 대한 기준 정답과 렌더를 비교한다. 지원하지 않는 proxy/custom entity는 손실 항목으로 표시한다.
- SKP/IFC/기타 3D: component instance 변환·단위·중첩·tag/scene 지원 여부를 항목별 판정한다. GLB 생성 성공만으로 원본 정보 추출 성공을 판정하지 않는다.
- HWP/HWPX/Office: 본문·표·문서구조·수식·페이지 근거의 지원 범위를 별도로 기록한다. 실제 구형/신형 파일을 모두 확인한다.
- PDF/OCR: 텍스트 정확도와 위치 정확도를 구분하며 숫자·단위·도면번호·날짜 누락을 별도로 평가한다.
- 아카이브: 압축 해제된 항목 수와 처리 상태가 원본 묶음에 역추적되어야 한다. 제한에 걸린 묶음은 내부 전수 처리가 완료되지 않은 것으로 표시한다.

## 운영 출시 판정

### Gate A — 코드 계약 검증

식별자·커서 원자성·멱등성·단위 변환·상태 전이·출처 참조 시험의 실제 결과와 재현 명령이 있어야 한다. 합성 fixture로 통과한 형식을 실제 파서 검증 완료로 확장하지 않는다.

### Gate B — 실제 Drive 인벤토리

범위 manifest, 시작/완료 시각, 전 페이지 처리 증거, 변경 재생 지점, 고유 항목 수, 범위별 실패, 현재 권한이 기록되어야 한다. 테스트용 실제 파일로 변경·접근 손실 시나리오를 확인하고, 전체 원본을 변경하는 시험은 하지 않는다.

### Gate C — 건축 콘텐츠 운영

형식별 품질 기준을 미리 정하고 실제 샘플과 기준 정답으로 충족해야 한다. 무관 분류 감사, 미분류 큐, 부분 추출, 미지원, 접근 불가를 숫자로 공개한다. 모든 관련 파일이 아티팩트 노드라는 사실은 모든 내용을 이해한다는 뜻이 아니다.

### Gate D — 법규 기능

승인된 규칙 버전, 적용성 판단, 단위와 측정 방법, 해당 규칙의 경계·예외 시험, 건축 검토자의 실제 사례 판정이 있어야 한다. 규칙 1개를 통과해도 다른 규칙은 별도 게이트를 거친다.
